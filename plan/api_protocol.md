# Спецификация сетевого протокола Penik Messenger (REST & WebSocket)

Этот документ описывает формат сетевого взаимодействия между клиентом и сервером Penik. Взаимодействие состоит из двух частей:
1. **REST API (HTTP)** — для авторизации, поиска контактов, изменения профиля и полной синхронизации истории сообщений.
2. **WebSocket (бинарный)** — для обмена мгновенными сообщениями и доставки в реальном времени.

---

## 1. REST API (HTTP)

Базовый URL: `http://<host>:<port>/api/v1`

Все запросы, требующие авторизации, должны содержать HTTP-заголовок `Authorization: Bearer <token>`.

### А. Регистрация пользователя
* **Запрос:** `POST /register`
* **Тело запроса (JSON):**
  ```json
  {
    "name": "Имя пользователя",
    "nickname": "username",
    "password": "секретный_пароль",
    "device_name": "Имя Устройства (например, Google Pixel 8)"
  }
  ```
* **Ответ (JSON):**
  ```json
  {
    "token": "JWT_TOKEN_STRING",
    "user_id": 12345,
    "device_id": 67890
  }
  ```

### Б. Авторизация (Вход)
* **Запрос:** `POST /login`
* **Тело запроса (JSON):**
  ```json
  {
    "nickname": "username",
    "password": "секретный_пароль",
    "device_name": "Имя Устройства"
  }
  ```
* **Ответ (JSON):**
  ```json
  {
    "token": "JWT_TOKEN_STRING",
    "user_id": 12345,
    "device_id": 67890
  }
  ```

### В. Поиск пользователей
* **Запрос:** `GET /users/search?q=<query_string>`
* **Ответ (JSON):**
  ```json
  [
    {
      "id": 54321,
      "nickname": "alex_ivanov",
      "name": "Алексей Иванов",
      "avatar_url": "/avatars/54321.jpg"
    }
  ]
  ```

### Г. Смена пароля
* **Запрос:** `PATCH /users/me/password`
* **Тело запроса (JSON):**
  ```json
  {
    "old_password": "старый_пароль",
    "new_password": "новый_пароль"
  }
  ```
* **Ответ:** `204 No Content`

### Д. Синхронизация истории сообщений (Sync Engine)
* **Запрос:** `GET /messages/history?limit=100&after_id=<max_local_msg_id>`
* **Ответ (JSON):**
  ```json
  [
    {
      "msg_id": 998877,
      "chat_id": 54321,
      "sender_id": 54321,
      "plaintext": "Привет! Как дела?",
      "created_at": 1784268000000,
      "delivered": 1
    }
  ]
  ```

## 2. Бинарный WebSocket

Для работы в реальном времени клиент устанавливает WebSocket-соединение.

* **URL для подключения:** `ws://<host>:<port>/api/v1/ws`
* **Авторизация:** Передается через субпротокол WebSocket. Заголовок запроса должен выглядеть так:
  ```http
  Sec-WebSocket-Protocol: access_token, <JWT_TOKEN_STRING>
  ```

### Формат фрейма (Wire Protocol)
Все сообщения WebSocket отправляются как **бинарные фреймы**. Каждое сообщение имеет следующий формат байтов:
* **Байт 0 (1 байт):** Опкод (тип события).
* **Байты 1+ (оставшиеся):** Полезная нагрузка (payload), сериализованная в бинарный формат **MessagePack**.

---

### 3. Спецификация опкодов и полезной нагрузки

#### `0x01` — MSG_SEND (Клиент -> Сервер)
Отправка сообщения собеседнику.
```json
{
  "to_user_id": 54321,
  "plaintext": "Привет, это сообщение из Android!",
  "msg_id": "8ca0cf9e-bd41-4c7b-b5d1-91a5e181e181" // UUID, сгенерированный клиентом
}
```

#### `0x02` — MSG_RECV (Сервер -> Клиент)
Получение входящего сообщения в реальном времени.
```json
{
  "from_user_id": 54321,
  "chat_user_id": 54321, // ID чата, в который попадает сообщение
  "plaintext": "Ответное сообщение",
  "msg_id": 998878, // Уникальный последовательный ID, назначенный сервером
  "ts": 1784268005000 // Таймстамп сервера в миллисекундах
}
```

#### `0x03` — MSG_ACK (Сервер -> Клиент)
Подтверждение от сервера, что отправленное клиентом сообщение сохранено в базу.
```json
{
  "msg_id": 998878, // Серверный ID
  "client_msg_id": "8ca0cf9e-bd41-4c7b-b5d1-91a5e181e181" // UUID, отправленный клиентом
}
```

#### `0x04` — MSG_DELIVERED (Клиент -> Сервер)
Клиент отправляет этот пакет при получении сообщения `MsgRecv` (`0x02`), чтобы сервер знал, что сообщение доставлено на конечное устройство получателя (для отрисовки двух галочек `✓✓`).
```json
{
  "msg_id": 998878 // Серверный ID полученного сообщения
}
```

#### `0x05` — OFFLINE_BATCH (Сервер -> Клиент)
Сервер отправляет этот пакет сразу после установления WebSocket соединения. Он содержит массив всех сообщений, которые были отправлены пользователю, пока он был оффлайн.
```json
{
  "msgs": [
    {
      "from_user_id": 54321,
      "chat_user_id": 54321,
      "plaintext": "Сообщение в оффлайне",
      "msg_id": 998877,
      "ts": 1784268001000
    }
  ]
}
```
*Примечание:* При получении пакета оффлайн-сообщений клиент обязан сохранить их в локальную базу данных и отправить на сервер пакеты `0x04` (MSG_DELIVERED) для каждого из них.

#### `0x06` — PING (Клиент <-> Сервер)
Пакет для проверки активности соединения. Payload отсутствует (пустой объект `{}`). Отправляется каждые 25-30 секунд.

#### `0x07` — PONG (Клиент <-> Сервер)
Ответ на PING. Payload отсутствует.

#### `0x08` — CHAT_PURGE (Сервер -> Клиент)
Команда от сервера на полную очистку истории чата на клиенте (например, если собеседник удалил чат для всех).
```json
{
  "peer_id": 54321 // ID собеседника, чей чат нужно очистить
}
```

#### `0x09` — CHAT_PURGE_ACK (Клиент -> Сервер)
Подтверждение очистки чата клиентом.
```json
{
  "peer_id": 54321
}
```
