# System Architecture & Cryptography — Penik Messenger

Penik Messenger — это кроссплатформенный мессенджер с поддержкой оконечного шифрования (End-to-End Encryption, E2EE), поддержкой нескольких устройств на аккаунт (Multi-Device), групповых чатов с эпохальными ключами и интеграции с VK CDN для передачи зашифрованных медиафайлов.

---

## 1. Cryptography Architecture (Схема шифрования)

### 1.1. Личные сообщения (1:1 Direct Messages)
- **Протокол:** Модифицированный протокол X3DH (Extended Triple Diffie-Hellman) и ChaCha20-Poly1305.
- **Алгоритмы:**
  - **Ключевой обмен:** X25519 (Curve25519).
  - **Деривация ключей:** HKDF-SHA256.
  - **Симметричное шифрование:** ChaCha20-Poly1305 (256-bit key, 96-bit nonce).
- **Multi-Device E2EE:**
  - Каждое устройство пользователя генерирует собственную пару ключей идентичности (`IK`) и подписанный ключ предзагрузки (`SPK`).
  - При отправке личного сообщения клиент получает через REST API (`GET /api/v1/keys/bundle/:user_id`) бандл ключей **всех активных устройств** получателя (а также дополнительных устройств самого отправителя).
  - Сообщение зашифровывается **отдельно для каждого целевого устройства** (payload содержит массив зашифрованных блоков под `device_id`).

### 1.2. Групповые чаты (Group E2EE)
- **Модель эпохальных ключей (Epoch Keys):**
  - Каждый групповой чат имеет текущую версию ключа группы (`KeyVersion`).
  - Для каждой версии ключа создаются **зашифрованные конверты (Envelopes)** — эпохальный ключ группы зашифровывается персонально для каждого устройства каждого участника группы.
- **Ротация ключей (Key Rotation):**
  - При изменении состава участников (добавление/исключение пользователя или устройства) генерируется новая версия ключа группы (`KeyVersion + 1`).
  - Заново шифруются и распространяются конверты ключей для актуальных устройств.
- **Шифрование сообщений в группе:**
  - Сообщение группы шифруется симметричным алгоритмом ChaCha20-Poly1305 с использованием ключа текущей эпохи группы (`KeyVersion`).
  - Сервер видит только маркер `KeyVersion`, зашифрованный payload, `salt` и `nonce`, не имея доступа к содержимому.

## 2. Device Pairing (Связывание устройств и передача истории)

Новое устройство (например, веб-клиент) может быть привязано к существующему аккаунту (например, на Android) через QR-код.

1. **Создание сессии:** Новое устройство вызывает `POST /api/v1/pairing/sessions` и генерирует одноразовый публичный ключ X25519.
2. **Сканирование:** Основное устройство сканирует QR-код (содержащий `session_id` и публичный ключ) и вызывает `POST /api/v1/pairing/sessions/claim`.
3. **Передача истории:** Основное устройство зашифровывает локальную баз данных/историю ключом, выведенным через ECDH (HKDF) с ключом сессии, и отправляет пакет через `PUT /api/v1/pairing/sessions/:id/history`.
4. **Импорт:** Новое устройство скачивает зашифрованную историю, расшифровывает её локально и сохраняет в IndexedDB.

## 3. Attachments Architecture (Вложения через VK CDN)

Для передачи тяжелых медиафайлов без нагружения сервера приложения используется проксирование через **VK CDN (VK Docs API)**:

1. **Загрузка (Upload):**
   - Клиент зашифровывает файл локально на клиенте (ChaCha20-Poly1305).
   - Зашифрованный файл отправляется на эндпоинт `POST /api/v1/attachments/vk-upload`.
   - Сервер приложения загружает зашифрованный блоб в VK Docs API и возвращает клиенту URL документов VK CDN.
2. **Скачивание (Download):**
   - Запрос на получение файла направляется на прокси-эндпоинт `GET /api/v1/attachments/proxy?url=...`.
   - Сервер проверяет домен в allowlist VK CDN, проксирует байты клиенту.
   - Клиент расшифровывает файл локальным ключом перед отображением.

## 4. Хранение данных (Persistence Layer)

### 4.1. Сервер (Go Backend)
- **База данных:** SQLite в режиме WAL (`modernc.org/sqlite`).
- **Сохраняемые сущности:**
  - `users` (учетные данные, хеши паролей Argon2id, публичные имена, никнеймы).
  - `devices` (устройства, публичные ключи IK, SPK, OPK).
  - `chats` & `messages` (метаданные и зашифрованные конверты сообщений для оффлайн-доставки).
  - `groups`, `group_members`, `group_key_versions`, `group_key_envelopes`.

### 4.2. Android клиент
- **База данных:** Room + SQLCipher (полное шифрование локальной БД на диске).
- **Сеть & Диагностика:** Retrofit (REST), OkHttp (WebSocket), Hilt (DI).

### 4.3. Веб-клиент (Browser)
- **База данных:** IndexedDB (для хранения зашифрованных сообщений, сессий, ключей).
- **Криптография:** Web Crypto API + WebAssembly (`libsodium`).
