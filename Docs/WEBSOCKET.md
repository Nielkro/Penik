# WebSocket Protocol Specification — Penik Messenger

Penik Messenger использует бинарный WebSocket протокол поверх протокола MessagePack.

---

## 1. Подключение и аутентификация

- **URL:** `ws://<host>:<port>/api/v1/ws` или `wss://...`
- **Аутентификация:** Передача токена сессии через заголовок WebSocket Subprotocol:
  ```http
  Sec-WebSocket-Protocol: access_token, <token_string>
  ```

---

## 2. Формат фреймов

Все сообщения передаются исключительно в виде **бинарных фреймов WebSocket** (Binary Frame).

Структура кадра (Wire Format):
```
+-------------------+------------------------------------------+
|  Opcode (1 byte)  |       MessagePack Payload (N bytes)      |
+-------------------+------------------------------------------+
```

- **Первый байт (Offset 0):** `Opcode` (0x01 ... 0x28).
- **Последующие байты (Offset 1..N):** Данные, упакованные в формат **MessagePack**.

---

## 3. Справочник опкодов (Opcodes Reference)

### 3.1. Личные сообщения (Direct Messages)

| Опкод | Название | Направление | Описание |
|-------|----------|-------------|----------|
| `0x01` | `MSG_SEND` | Клиент → Сервер | Отправка зашифрованного сообщения адресату |
| `0x02` | `MSG_RECV` | Сервер → Клиент | Доставка зашифрованного сообщения получателю |
| `0x03` | `MSG_ACK` | Сервер → Клиент | Подтверждение сохранения сообщения сервером |
| `0x04` | `MSG_DELIVERED` | Клиент → Сервер | Отметка о доставке на устройство получателя |
| `0x05` | `OFFLINE_BATCH` | Сервер → Клиент | Пачка пропущенных сообщений при подключении |
| `0x0A` | `MSG_DELETE` | Клиент → Сервер | Запрос на удаление сообщения (в т.ч. у всех) |
| `0x0B` | `MSG_DELETE_NOTIFY` | Сервер → Клиент | Уведомление собеседника об удалении сообщения |
| `0x16` | `MSG_RETRY_REQ` | Клиент → Сервер | Запрос повторной отправки при ошибке расшифровки |
| `0x17` | `MSG_RETRY_RESP` | Сервер → Клиент | Ответ с перезашифрованным сообщением |
| `0x18` | `MSG_READ` | Клиент → Сервер | Отметка о прочтении сообщения |
| `0x1B` | `MSG_STATUS_BATCH` | Сервер → Клиент | Обновление статусов доставки/прочтения |

---

### 3.2. Системные события и Presence

| Опкод | Название | Направление | Описание |
|-------|----------|-------------|----------|
| `0x06` | `PING` | Оба | Проверка соединения |
| `0x07` | `PONG` | Оба | Ответ на PING |
| `0x08` | `CHAT_PURGE` | Сервер → Клиент | Принудительная очистка чата локально |
| `0x09` | `CHAT_PURGE_ACK` | Клиент → Сервер | Подтверждение выполнения очистки чата |
| `0x1C` | `USER_AVATAR_UPDATE` | Сервер → Клиент | Сигнал об изменении аватара пользователя |
| `0x1D` | `PRESENCE_UPDATE` | Сервер → Клиент | Изменение статуса Онлайн / Был в сети |
| `0x1E` | `SERVER_SHUTDOWN` | Сервер → Клиент | Уведомление о плановом выключении сервера |

---

### 3.3. Ключи и пейринг устройств (Keys & Pairing)

| Опкод | Название | Направление | Описание |
|-------|----------|-------------|----------|
| `0x10` | `KEY_FETCH_REQ` | Клиент → Сервер | Запрос ключей девайсов |
| `0x11` | `KEY_FETCH_RESP` | Сервер → Клиент | Ответ со связкой ключей девайсов |
| `0x12` | `KEY_PUBLISH` | Клиент → Сервер | Публикация нового X25519 ключа |
| `0x13` | `KEY_BUNDLE_RESP` | Сервер → Клиент | Ответ с бандлом ключей |
| `0x14` | `KEY_BUNDLE_REQ` | Клиент → Сервер | Запрос бандла ключей |
| `0x15` | `REFILL_PRE_KEYS` | Сервер → Клиент | Запрос сервера пополнить одноразовые ключи |
| `0x19` | `PAIRING_HISTORY_READY`| Сервер → Клиент | Уведомление о готовности передачи истории |
| `0x1A` | `PAIRING_CLAIMED` | Сервер → Клиент | Уведомление о сканировании QR-кода новым девайсом |

---

### 3.4. Групповые чаты (Group Messaging)

| Опкод | Название | Направление | Описание |
|-------|----------|-------------|----------|
| `0x20` | `GROUP_MSG_SEND` | Клиент → Сервер | Отправка зашифрованного сообщения в группу |
| `0x21` | `GROUP_MSG_RECV` | Сервер → Клиент | Доставка сообщения группы участнику |
| `0x22` | `GROUP_MSG_ACK` | Сервер → Клиент | Подтверждение приема сообщения группы |
| `0x23` | `GROUP_KEY_AVAILABLE` | Сервер → Клиент | Сигнал о появлении нового конверта ключа |
| `0x24` | `GROUP_MEMBER_CHANGED` | Сервер → Клиент | Сигнал об изменении состава участников группы |
| `0x25` | `GROUP_MSG_DELIVERED` | Клиент → Сервер | Отметка о доставке группового сообщения |
| `0x26` | `GROUP_MSG_READ` | Клиент → Сервер | Отметка о прочтении группового сообщения |
| `0x27` | `GROUP_HISTORY_READY` | Сервер → Клиент | Сигнал о наличии пакета истории для нового участника |
| `0x28` | `GROUP_AVATAR_UPDATE` | Сервер → Клиент | Уведомление об изменении аватара группы |

---

## 4. Структуры MessagePack payloads

### `0x01` MSG_SEND (Зашифрованный вариант)
```json
{
  "to_user_id": 42,
  "msg_id": "client-uuid-v4",
  "reply_to_msg_id": "optional-parent-uuid",
  "devices": [
    {
      "device_id": 1,
      "ciphertext": "<binary_bytes>",
      "salt": "<binary_bytes>",
      "nonce": "<binary_bytes>"
    }
  ]
}
```

### `0x02` MSG_RECV
```json
{
  "from_user_id": 10,
  "from_device_id": 1,
  "recipient_device_id": 2,
  "from_identity_key": "<binary_bytes>",
  "chat_user_id": 10,
  "msg_id": 100500,
  "client_msg_id": "client-uuid-v4",
  "reply_to_msg_id": null,
  "ciphertext": "<binary_bytes>",
  "salt": "<binary_bytes>",
  "nonce": "<binary_bytes>",
  "ts": 1770550000
}
```

### `0x1D` PRESENCE_UPDATE
```json
{
  "user_id": 42,
  "online": true,
  "last_seen": 1770550123
}
```

### `0x20` GROUP_MSG_SEND
```json
{
  "group_id": 5,
  "message_id": "client-uuid-v4",
  "reply_to_msg_id": null,
  "key_version": 2,
  "ciphertext": "<binary_bytes>",
  "salt": "<binary_bytes>",
  "nonce": "<binary_bytes>",
  "created_at": 1770550000
}
```
